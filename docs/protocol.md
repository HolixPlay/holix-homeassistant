# Holix Local Control Protocol (HLCP) — version 1

> Türkçe sürüm: [protokol.tr.md](protokol.tr.md).

The local-network control endpoint opened by the Holix Play app (Apple TV, iPhone/iPad, Mac,
Android/Android TV, later HarmonyOS, Windows). The first client is the Home Assistant integration
(`custom_components/holix`); the same endpoint may later be used by other home systems and by Holix's
own remotes.

This document is the **normative contract**. Machine-readable schema: [`protocol.schema.json`](protocol.schema.json)
(JSON Schema 2020-12). Conformance check: `tools/holix_probe.py` (see §10).
The key words MUST / SHOULD / MAY are to be interpreted as described in RFC 2119.

## 1. Roles and transport

- **Device (server):** the Holix Play app. It listens only while the app is **in the foreground**
  (on tvOS/iOS the process is suspended in the background; when moving to the background the app closes
  connections with `4002`, withdraws its mDNS advertisement, and reopens both when it returns to the
  foreground).
- **Client:** Home Assistant (or `holix_probe`).
- Transport: WebSocket (RFC 6455) over plain TCP, path **`/holix/v1`**. Default port **47861**;
  if the port is taken the device picks another port and advertises it over mDNS (the client always takes
  the port from mDNS/configuration).
- Each frame is a single UTF-8 JSON object (text frame). Binary frames are not used.
- Every object MUST have `type` (string). Unknown fields are **ignored** on both sides (forward
  compatibility). An unknown `type` is answered by the device with an `unknown_type` error (if it has an
  `id`) and ignored by the client.
- At least **4** concurrent authorized connections are supported; state and events are broadcast to all.
- Liveness: the client sends a WebSocket ping frame every 30 s (the device's WS library answers with pong).
  An application-level `ping` → `pong` is also supported. The device MAY close a connection that has
  received no frame for 90 s.
- No TLS in version 1 (local network). The token is **never** sent in clear over the network — except
  once, during pairing (see §4, limitation in §11).

## 2. Discovery (mDNS / DNS-SD)

- Service type: **`_holixplay._tcp.local.`**
- Instance name: the user's device name (e.g. `Living Room Apple TV`), at most 63 bytes.
- SRV: the device's IP and listening port.
- TXT records (all REQUIRED, lowercase keys):

| Key | Example | Meaning |
|---|---|---|
| `id` | `5b0c1d9e-3f0a-4c55-9a43-1f0e2b7a9c10` | Persistent device ID (UUID v4, generated at install, stored in Keychain/SharedPreferences; may change on reinstall). This is the HA `unique_id`. |
| `proto` | `1` | Protocol major version. |
| `path` | `/holix/v1` | WebSocket path. |
| `platform` | `tvos` | `tvos` `ios` `ipados` `macos` `visionos` `android` `androidtv` `harmonyos` `windows` |
| `model` | `AppleTV14,1` | Hardware model (Apple: `hw.machine`; Android: `Build.MODEL`). |
| `ver` | `0.4.0` | App version. |

Apple: `Info.plist` → `NSBonjourServices = ["_holixplay._tcp"]`, `NSLocalNetworkUsageDescription`.
Listening via `NWListener` (`service: NWListener.Service(name:type:"_holixplay._tcp", txtRecord:)`).
Android: `NsdManager.registerService` (`serviceType = "_holixplay._tcp"`), network permission `INTERNET`.

## 3. Message envelopes

| Direction | `type` | Fields |
|---|---|---|
| D→C | `hello` | first message on connect, without waiting for a request |
| C→D | `pair_start`, `pair_finish`, `auth`, `command`, `subscribe_colors`, `unsubscribe_colors`, `ping` | all carry `id` (positive integer, increasing within the connection, generated by the client) |
| D→C | `result` | **exactly one** response per request, same `id` |
| D→C | `state`, `event`, `colors` | only to authorized connections, unsolicited |

(D = device, C = client.)

**result:**
```json
{"type": "result", "id": 7, "success": true, "result": {}}
{"type": "result", "id": 7, "success": false, "error": {"code": "invalid_args", "message": "position < 0"}}
```
The `result` object is REQUIRED on success (may be empty). `message` is for humans; the client looks only
at `code`.

**Error codes:** `unauthorized` (a message requiring authorization on an unauthorized connection),
`invalid_auth`, `invalid_pin`, `pairing_not_started`, `too_many_attempts`, `unknown_type`,
`unknown_command`, `invalid_args`, `not_supported` (the device/platform cannot do it, e.g. volume on tvOS),
`not_available` (cannot be applied right now, e.g. `seek` while nothing is playing), `internal`.

**Close codes (WebSocket close):** `4000` protocol error, `4001` authorization revoked (the user removed the
pairing in the app → the client asks for re-pairing), `4002` app going to the background / shutting down
(the client tries to reconnect), `4003` connection limit exceeded.

## 4. Hello, pairing, authorization

### 4.1 hello (device → client, immediately on connect)
```json
{
  "type": "hello",
  "proto": 1,
  "device": {"id": "5b0c1d9e-…", "name": "Living Room Apple TV", "model": "AppleTV14,1",
             "platform": "tvos", "app_version": "0.4.0 (57)"},
  "nonce": "q0n3eW5yZ0ZzYk1sT0dtVg",
  "capabilities": ["playback", "profiles", "ambilight", "colors", "notify", "keys"]
}
```
- `nonce`: **fresh** per connection, at least 16 random bytes, base64url (unpadded).
- `capabilities` (whatever the device supports): `playback` (state + playback commands), `volume`
  (`set_volume`/`mute` can be applied), `profiles`, `ambilight` (a Holix ambilight output exists),
  `colors` (color stream, §8), `notify` (on-screen notification), `keys` (navigation keys), `play_item`.
- If `proto` is greater than what the client knows, the client closes the connection and reports
  "the app is newer".

### 4.2 Pairing (once; PIN on screen)
```json
→ {"type": "pair_start", "id": 1, "client_id": "2d8f…", "client_name": "Home Assistant (Home)"}
← {"type": "result", "id": 1, "success": true, "result": {"pin_length": 6, "expires_in": 120}}
```
The device shows a 6-digit PIN and the `client_name` on screen (a full-screen card on TV, a sheet on iPhone).
The PIN is `0–9`, valid for 120 s, one pairing at a time (a new `pair_start` invalidates the previous one).
```json
→ {"type": "pair_finish", "id": 2, "client_id": "2d8f…", "pin": "482913"}
← {"type": "result", "id": 2, "success": true, "result": {"token": "Zk8x…43 characters"}}
```
- `token`: 32 random bytes, base64url (unpadded) → 43 characters. The device stores `client_id → token`
  (Keychain / EncryptedSharedPreferences). If the same `client_id` pairs again, the old token is deleted.
- Errors: `pairing_not_started` (none / expired / different `client_id`), `invalid_pin` (the remaining
  attempts are in `error.message`, not in `result`), `too_many_attempts` on the 5th wrong PIN and the
  pairing is cancelled.
- After pairing the connection is still **unauthorized**; the client sends `auth` on the same connection.
- The app settings contain a "Connected home systems" list: name, pairing date, last connection, **Remove**
  (→ the token is deleted and any open connection is closed with `4001`).

### 4.3 auth (on every connection)
```json
→ {"type": "auth", "id": 3, "client_id": "2d8f…", "hmac": "<64 hex>"}
← {"type": "result", "id": 3, "success": true, "result": {}}
← {"type": "state", "state": {…}}          // full state right after
```
`hmac = hex(HMAC-SHA256(key = UTF-8(token), msg = UTF-8(nonce)))`, lowercase. The token never travels over
the network; since the `nonce` is per connection, replay is useless. The comparison must be constant-time.
Error: `invalid_auth` (unknown `client_id` or wrong HMAC) → the client switches to the re-pairing flow.
The device MAY close an unauthorized connection that does not `auth`/pair within 30 s. On an unauthorized
connection only `pair_start`, `pair_finish`, `auth`, `ping` are accepted; everything else gets
`unauthorized`.

Test vector: token `dGVzdC10b2tlbi0wMDAwMDAwMDAwMDAwMDAwMDAwMDA`, nonce `bm9uY2UtMDAwMDAwMDAwMA`
→ hmac `c607ad23048f0e5684d11cd65c51c128405a1e20d6615ce89af5b1cc2cea5c7d`
(verified in `tests/test_protocol.py`; to be copied verbatim into core/client tests).

## 5. State (`state`)

Sent to authorized connections right after a successful `auth` and on **every meaningful change**, as a full
snapshot (no patches — the object is small). The playback position is not streamed: with `position` +
`position_at` (the moment the position was measured, Unix ms) + `rate` the client advances it itself.
The device sends `state` when the playback state, item, profile, audio/subtitle track, segment, ambilight or
screensaver changes, on seek, and at least every 60 s while playing. At most 4 per second (when they pile
up, the latest state is sent).

```json
{
  "type": "state",
  "state": {
    "playback": {
      "state": "playing",
      "position": 1834.2, "duration": 7421.0, "position_at": 1792152000123, "rate": 1.0,
      "item": {
        "id": "a1b2c3d4e5f60718293a4b5c6d7e8f90", "type": "episode",
        "title": "Ozymandias", "series_title": "Breaking Bad", "season": 5, "episode": 14,
        "year": 2013, "official_rating": "TV-MA",
        "image_url": "https://jf.example.net/Items/a1b2…/Images/Primary?maxWidth=600&tag=…"
      },
      "video": {"dynamic_range": "dolby_vision", "width": 3840, "height": 2160,
                "codec": "hevc", "frame_rate": 23.976},
      "audio": {"codec": "eac3", "channels": 6, "spatial": true, "language": "eng"},
      "subtitle": {"language": "tur", "forced": false},
      "segment": null,
      "play_method": "direct_play",
      "volume": null, "muted": false
    },
    "profile": {"id": "p-alex", "name": "Alex", "kind": "adult"},
    "profiles": [
      {"id": "p-alex", "name": "Alex", "kind": "adult"},
      {"id": "p-kids", "name": "Kids", "kind": "child"},
      {"id": "p-guest", "name": "Guest", "kind": "guest"}
    ],
    "ambilight": {"on": true, "brightness": 0.8, "targets": 2},
    "screensaver": false
  }
}
```

| Field | Type | Rule |
|---|---|---|
| `playback.state` | `idle` `playing` `paused` `buffering` | `idle` = player closed (browsing/menu) |
| `position`, `duration` | number (s) \| null | null when `idle`; `duration` null for live TV |
| `position_at` | integer (Unix ms) \| null | when `position` was measured (device clock; assumed NTP-synced) |
| `rate` | number | not 0 while paused but the last rate; the client advances while `state=="playing"` |
| `item` | object \| null | null when `idle` |
| `item.id` | string | Jellyfin `ItemId` (32 hex) |
| `item.type` | `movie` `episode` `trailer` `music_video` `live_tv` `audio` `video` `other` | |
| `item.series_title` `season` `episode` `year` `official_rating` `image_url` | \| null | `image_url` is an absolute URL; it does **not** contain a Jellyfin `api_key` (uses the public cache tag) |
| `video.dynamic_range` | `sdr` `hdr10` `hdr10_plus` `dolby_vision` `hlg` | the format **actually output** (`hdr10` on DV→HDR10 fallback) |
| `video.codec` / `audio.codec` | string | Jellyfin codec names (`hevc`, `av1`, `h264`, `eac3`, `truehd`, `aac` …) |
| `audio.spatial` | bool | Atmos / DTS:X / spatial audio active |
| `audio.language` `subtitle.language` | ISO 639-2 \| null | |
| `subtitle` | object \| null | null = subtitles off |
| `segment` | `intro` `outro` `recap` `preview` `commercial` \| null | Jellyfin media segment, if currently inside one |
| `play_method` | `direct_play` `direct_stream` `transcode` \| null | |
| `volume` | 0–1 \| null | null = the app does not control volume (tvOS, HDMI-CEC) |
| `profile` | object \| null | null = profile picker screen |
| `profile.kind` | `adult` `child` `guest` | |
| `profiles` | array | includes PIN-protected profiles; switching to a PIN-protected profile returns `not_available` (§6) |
| `ambilight` | object \| null | null = no ambilight on the device / not configured; `targets` = number of connected LED controllers |
| `screensaver` | bool | in-app screensaver (photo frame) is on |

## 6. Commands

```json
→ {"type": "command", "id": 9, "command": "seek", "args": {"position": 600}}
← {"type": "result", "id": 9, "success": true, "result": {}}
```
`args` is always an object (may be empty; treated as `{}` if absent). On success the new state arrives
separately as `state`; `result` carries no state.

| `command` | `args` | Notes / errors |
|---|---|---|
| `play` | — | `not_available` (no item) |
| `pause` | — | |
| `play_pause` | — | |
| `stop` | — | closes the player → `idle` |
| `next` / `previous` | — | next/previous episode or queue item |
| `seek` | `position` (s, ≥0) | `invalid_args` |
| `set_volume` | `level` (0–1) | `not_supported` (without the `volume` capability) |
| `mute` | `muted` (bool) | `not_supported` |
| `select_profile` | `profile_id` | `invalid_args` (no such profile), `not_available` (PIN-protected or playback in progress) |
| `set_ambilight` | `on`? (bool), `brightness`? (0–1) | at least one; `not_supported` |
| `play_item` | `item_id` (Jellyfin), `position`? (s) | plays as the active profile; `not_available` (no profile / age restriction) |
| `notify` | `message`, `title`?, `duration`? (s, 1–60, default 8) | on-screen toast; does not stop playback |
| `key` | `key`: `up` `down` `left` `right` `select` `back` `home` `menu` `play_pause` | in-app navigation |

Age restrictions and PIN rules **cannot** be bypassed by commands (`play_item` of adult content on a child
profile → `not_available`).

## 7. Events (`event`)

```json
{"type": "event", "event": "playback_started", "ts": 1792152000123,
 "data": {"item": {…}, "video": {…}, "audio": {…}, "profile": {…}}}
```

| `event` | `data` | When |
|---|---|---|
| `playback_started` | `item`, `video`, `audio`, `profile` | a new item started playing (including moving to the next episode) |
| `playback_paused` | `item`, `position` | paused by the user/a command (not buffering) |
| `playback_resumed` | `item`, `position` | |
| `playback_stopped` | `item`, `position`, `duration`, `reason` (`ended` `user` `error`) | |
| `segment_started` / `segment_ended` | `segment`, `item` | intro/outro/recap/preview/commercial boundary (`outro` = credits → turn the lights on) |
| `profile_changed` | `profile` (\| null) | |
| `screensaver_started` / `screensaver_stopped` | `{}` | |

Event order: `state` first, then `event` (when the client handles the event, its state is current).
`item`, `video`, `audio`, `profile` use the same schemas as in §5.

## 8. Color stream (`colors`) — using HA lights as ambilight targets

Holix ambilight's own LED path (DDP/WLED etc.) is independent of this; this stream is only for driving
**Wi-Fi/Zigbee lamps through HA** and is low-rate.
```json
→ {"type": "subscribe_colors", "id": 11, "fps": 4}
← {"type": "result", "id": 11, "success": true, "result": {"fps": 4}}
← {"type": "colors", "seq": 1, "ts": 1792152000123,
   "zones": {"left": [12, 30, 80], "right": [10, 28, 70], "top": [5, 5, 20],
             "bottom": [40, 30, 10], "center": [60, 60, 60], "average": [25, 30, 52]}}
→ {"type": "unsubscribe_colors", "id": 12}
```
- `fps` 1–30 is requested; the device reports the actual rate in `result.fps` (it may stream even while
  ambilight is off; colors are derived from the video edges). `colors` is sent only while playing.
- Zones are fixed: `left` `right` `top` `bottom` (average of the edge strips), `center`, `average`;
  each `[r, g, b]` 0–255, sRGB, with the ambilight saturation/gamma settings applied, **brightness not
  scaled**. `seq` starts at 1 per connection and increases.
- `colors` is not sent without a subscription; the subscription is dropped when the connection drops.

## 9. Versioning

- Backward-compatible additions (new field, new event, new command, new capability) do not bump `proto`.
- A breaking change bumps `proto` to 2 and the path to `/holix/v2`; the device serves both for a while.

## 10. Conformance

- `docs/protocol.schema.json`: schema for all messages (each `type` under `$defs`).
- `tools/holix_probe.py <host> [--port 47861]`: connects to the real app, pairs (asks for the PIN),
  performs `auth`, validates every incoming message against the schema, and optionally tries commands.
  Platform implementations are verified with it. In addition, `tests/fake_device.py` is the reference
  device implementation (Python, `aiohttp`): where behavior is ambiguous, it is the reference.
- Core/client tests adopt the §4.3 HMAC test vector and the sample messages in `tests/fixtures/*.json`.

## 11. Security notes

- During pairing the token travels once over plain WebSocket; an attacker sniffing the network at that
  moment could capture it. Accepted risk (local network, PIN confirmation on screen). Version 2 candidate:
  key derived from the PIN via PAKE (SPAKE2).
- Commands are not signed individually within a session; hijacking the TCP session requires a MITM on the LAN.
- The device MUST accept connections only from private addresses (RFC 1918, ULA `fc00::/7`, link-local).
- `image_url` and event data DO NOT contain a Jellyfin access token, user password or PIN.
